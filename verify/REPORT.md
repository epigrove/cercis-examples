## 五、值类型：这次真正落地的部分

本次把"类型"从散落的判断收成**内核唯一一份实现**（需求文档 §5.9 / D36）：

| 变化 | 现象（改之前） | 现在 |
|---|---|---|
| 检查规则 | 内核与插件各写一套：`1e3`、`2026/6/15` 在插件里算合法 | 插件读内核 `value-types --json` 的机器规则（regex / enum / builtin） |
| 允许值 | 只在插件里当**提醒** | 内核定为**错误**级，写入前拦下（本条直接抓出 F-08） |
| 小数位数 / 范围 | 无 | 提醒级（`precision` / `range`），不拦数据 |
| 写入前 | 插件自己判 | `append` / `append-many` 有结构错误即整批不写（`--force` 可越权，会留痕） |
| 类型推断 | 无 | `cercis infer-types`：候选 + 置信度 + 反例；**≥95% 才给强建议**，永不自动改模板 |
| 改模板 | 手工编辑 YAML | `cercis set-field-type`：先出影响预览（会新增几处错误、在第几行），会拦下会引入错误的改动 |

证据（自动化）：

- 内核 `value.rs` 8 项 + `infer.rs` 8 项单元测试；
- `cercis-kit-core/tests/type_consistency.rs`：跨进程跑**真内核**，对同一批好值/坏值
  逐个比对"插件认为错的格子"与"内核认为错的格子"，必须完全一致；
  实测把插件的日期判断故意改错，测试立刻变红（不是摆设）；
- 契约快照（`tests/fixtures/value-types.json`）与真内核 `value-types --json` 的
  值域清单与 `matcher` 逐项比对，规则一变就提醒更新。

## 六、发现的问题（F 系列）

| 编号 | 问题 | 状态 |
|---|---|---|
| F-01 | 模板外的系统表（`corrections`/`change_log`）导不出来 | ✅ 已修 |
| F-02 | 父样本引用缺失，子样本指向不存在的父样本检不出来 | ✅ 已修 |
| F-03 | 宽表导入需要 `--allow-new-columns` 才能加列 | ✅ 已修 |
| F-04 | 宽表行身份应优先取**必填引用列**（可 `--index` 覆盖） | ✅ 已修 |
| F-05 | 换模板后残留空表（`records.csv`）只被提示，未被引导清理 | ⏳ 留 S7 向导（本期体检列为 info：3 条） |
| F-06 | 说明书里命令名与内核不一致 | ✅ 已修 |
| F-07 | 自引用列（`parent_sample_id`）在同批导入时误判为断链 | ✅ 已修 |
| **F-08** | 数据里的生育期写作"分蘖期/抽穗期/成熟期"，模板允许值是"分蘖/抽穗/成熟"——**允许值升级为错误级后当场拦下导入** | ✅ 已修：统一为带"期"的规范写法（模板侧），数据与模板从此同一套词 |

F-08 值得记一笔：它不是"数据错了"，而是**同一件事有两套写法**。允许值只在提醒级时，
这类不一致会悄悄进入数据、等到统计阶段才发现；升为错误级之后，它在写入前就被挡住了——
这正是 §5.9 把 `allowed_values` 定为错误的理由。

## 八、复跑方法

